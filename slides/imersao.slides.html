Nivelamento · Databricks · lakehouse

Data warehouse + data lake = lakehouse

Data warehouse
  • tabelas organizadas, SQL rápido, dashboards
  • caro e rígido; não guarda planilha, PDF, JSON
Data lake
  • guarda qualquer arquivo, barato
  • vira um "pântano": ninguém sabe o que tem, nem confia
Lakehouse
  • os arquivos ficam no lake, mas com tabela de verdade por cima (Delta)
  • governança num catálogo só (Unity Catalog)
  • SQL, BI, ML e IA sobre o mesmo dado

No Projeto Farol: as planilhas, os JSON e os XML entram como arquivo no volume e viram tabela no mesmo catálogo. É o lakehouse na prática.

-- um bloco por arquivo; o mesmo comando para
-- CSV, Excel, JSON e XML
CREATE OR REPLACE TABLE
  lakehouse_vertice.bronze.projetos AS
SELECT * EXCEPT (_rescued_data)
FROM read_files(
  '/Volumes/lakehouse_vertice/bronze/raw/pmo/projetos.csv',
  format => 'csv', header => true,
  inferColumnTypes => false);

inferColumnTypes => false: tudo entra como texto, para a sujeira aparecer. _rescued_data: a coluna "rede de segurança" que o read_files cria sozinho; o que não cabe nas colunas cai ali em vez de sumir. Nos nossos arquivos vem vazia, então o EXCEPT tira.
